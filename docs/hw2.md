# HW2 — Синтаксический анализ и AST

Реализация синтаксического анализа программ на языке Funny, интегрировать парсер с лексическим анализатором из HW1, построить абстрактное синтаксическое дерево (AST) и реализовать обработку синтаксических ошибок с указанием их положения в исходной программе.

Парсер должен поддерживать функции и формулы, выражения, условия, предикаты, массивы, присваивания, условные операторы, циклы, блоки, `assert` и `assume`.

---

## Метод синтаксического анализа

Для синтаксического анализа выбран метод рекурсивного спуска (recursive descent).

Каждой основной конструкции грамматики соответствует отдельная функция парсера. Например:

* `parseExpr` — разбор выражений;
* `parseCondition` — разбор условий;
* `parsePredicate` — разбор предикатов;
* `parseStatement` — разбор операторов;
* `parseFunction` — разбор функций;
* `parseFormula` — разбор формул;
* `parseProgram` — разбор программы целиком.

Парсер работает непосредственно с последовательностью токенов, полученной от лексического анализатора HW1.

Для выражений и логических конструкций используются отдельные уровни разбора, соответствующие приоритетам операторов. Это позволяет непосредственно построить AST с правильной структурой.

Для различения функции и формулы используется дополнительный просмотр токенов до соответствующей закрывающей скобки. Если после списка параметров следует `=>`, конструкция рассматривается как формула; в противном случае — как функция.

Таким образом, реализация использует recursive descent с дополнительным lookahead для отдельных неоднозначных конструкций.

### Операторы

```text
statement =
    assignment
  | conditional
  | loop
  | block
  | assertStmt
  | assumeStmt
```

Присваивание:

```text
assignment =
    varName "=" expr ";"
  | arrayAccess "=" expr ";"
  | varName { "," varName } "=" functionCall ";"
```

Условный оператор:

```text
conditional =
    "if" "(" condition ")" statement ["else" statement]
```

Цикл:

```text
while =
    "while" "(" condition ")"
    [ "invariant" predicate ]
    statement
```

Блок:

```text
block =
    "{" { statement } "}"
```

Проверки:

```text
assertStmt = "assert" predicate ";"
assumeStmt = "assume" predicate ";"
```

### Выражения

Поддерживаются:

* переменные;
* целые числа;
* вызовы функций;
* доступ к элементу массива;
* унарный минус;
* бинарные арифметические операции;
* скобочные выражения.

Для арифметических операций используется следующий приоритет:

```text
* /
  ↓
+ -
```

Например, выражение

```text
a + b * 2
```

строится в AST как:

```text
a + (b * 2)
```

### Доступ к массиву

Поддерживается конструкция:

```text
a[i]
```

а также присваивание:

```text
a[i] = expr;
```

### Условия

Поддерживаются:

```text
true
false
comparison
not condition
condition and condition
condition or condition
condition -> condition
(condition)
```

Приоритет операторов:

```text
not
  ↓
and
  ↓
or
  ↓
->
```

Импликация `->` разбирается с правой ассоциативностью.

Например:

```text
not (a < 0) and b > 0 or a == b
```

строится как:

```text
((not (a < 0)) and (b > 0)) or (a == b)
```

### Предикаты

Поддерживаются:

```text
true
false
comparison
not predicate
predicate and predicate
predicate or predicate
(predicate)
quantifier
formulaRef
```

Для логических операций используется порядок:

```text
not
  ↓
and
  ↓
or
```

### Кванторы

Поддерживается форма:

```text
forall(x: int | predicate)
exists(x: int | predicate)
```

### Функции

Функция имеет структуру:

```text
identifier "(" [ variableDef {"," variableDef } ] ")"
["requires" predicate]
"returns" variableDef {"," variableDef }
["ensures" predicate]
["uses" localVarDef {"," localVarDef }]
statement
```

Поддерживаются типы:

```text
int
int[]
```

### Формулы

Поддерживается форма:

```text
identifier "(" [variableDef {"," variableDef}] ")" "=>" predicate
```

## Абстрактное синтаксическое дерево

После успешного синтаксического анализа парсер строит AST.

Корневым узлом является:

```text
Program
```

который содержит списки функций и формул.

Основные узлы AST:

```text
Program
Function
Formula
Variable

Assignment
Block
If
While
Assert
Assume

NumberExpr
VariableExpr
UnaryExpr
BinaryExpr
CallExpr
ArrayAccessExpr

BoolCondition
Comparison
NotCondition
BinaryCondition

BoolPredicate
PredicateComparison
NotPredicate
BinaryPredicate
Quantifier
FormulaRef
```

Интерфейсы `Statement`, `Expr`, `Condition` и `Predicate` используются для разделения различных категорий узлов AST.

Например, выражение:

```text
result = a + b * 2;
```

представляется структурой:

```text
Assignment
  Variables:
    Variable result
  Value:
    Binary +
      Left:
        Variable a
      Right:
        Binary *
          Left:
            Variable b
          Right:
            Number 2
```

Таким образом, AST сохраняет синтаксическую структуру программы и приоритеты операторов.

AST также имеет отдельный текстовый принтер, позволяющий просматривать результат разбора программы.

## Обработка ошибок

Парсер сообщает синтаксические ошибки с указанием позиции в исходном тексте.

Каждая ошибка содержит:

* номер строки;
* номер столбца;
* описание ожидаемой и фактически полученной конструкции.

Например:

```text
2:11: expected ";", got "&"
```

При обнаружении ошибки парсер не должен зацикливаться.

Для некоторых конструкций используется восстановление после ошибки. Например, при ошибке внутри присваивания парсер пропускает оставшиеся токены текущей конструкции до `;` или `}` и продолжает разбор программы.

Это позволяет избежать каскада дополнительных ошибок, вызванных одной исходной синтаксической ошибкой.

Например, для программы с недопустимым оператором:

```text
result = a & b;
```

парсер сообщает основную ошибку:

```text
2:11: expected ";", got "&"
```

вместо последовательности вторичных ошибок, возникающих из-за продолжения разбора уже некорректной конструкции.

Для пустого входа также формируется диагностическое сообщение:

```text
1:1: expected function or formula, got end of input
```

## Интеграция с лексическим анализатором

Парсер использует токены, полученные от лексического анализатора HW1.

Каждый токен содержит:

* тип;
* значение;
* позицию в исходном тексте.

Позиция включает:

```text
Offset
Line
Column
```

Лексический анализатор добавляет специальный токен `EOF`, который используется парсером для определения конца входной программы.

Недопустимые символы представлены токенами типа `ERROR` и приводят к диагностике с указанием позиции.

---



### Массивы

Присваивание элементу массива:

```text
a[i] = value;
```

представляется непосредственно как `Assignment`, у которого левое выражение является `ArrayAccessExpr`.

Семантическое преобразование такой конструкции в функциональную операцию копирования массива выполняется на последующих этапах и не является задачей синтаксического анализатора.

## Запуск

Парсер запускается командой:

```text
go run ./cmd/parser <source-file>
```

Например:

```text
go run ./cmd/parser examples/test.fun
```

При успешном разборе выводится:

```text
Parsing successful
```

после чего печатается AST программы.

При наличии синтаксических ошибок выводятся диагностические сообщения с указанием строки и столбца, после чего программа завершается с ненулевым кодом возврата.
